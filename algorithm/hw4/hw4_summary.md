### 1. 일반 설명 (General Description)
0-1 배낭 문제(Knapsack Problem)를 다음 4가지 방법으로 해결하는 C++ 프로그램을 작성하세요.
1. Brute Force (완전 탐색)
2. Greedy (탐욕 알고리즘) - 단, Fractional Knapsack 문제로 구현할 것
3. Dynamic Programming (동적 계획법)
4. Branch and Bound (분기한정법)

### 2. 구현 세부 사항 (Implementation Details)
- **DP & B&B**: 수업 시간에 배운 대로 구현
- **Greedy**: 0-1 배낭이 아닌 Fractional 배낭 문제로 풀이
- **Brute-force**: AI 생성 코드나 인터넷 코드 직접 사용 가능

## [2] 작성 파트 (Writing Part)

**1. (a) 과제를 수행하면서 겪은 어려움 (Difficulties encountered)**
- **메모리 초과 문제**: 동적 계획법(DP)을 구현할 때, 아이템의 개수가 $N=10,000$ 수준으로 커졌을 때 단순히 $O(N \times W)$ 크기의 2차원 배열을 동적 할당하려고 하니 메모리 초과(Segmentation Fault 등) 문제가 발생하여 어려움을 겪었습니다.
- **분기한정법(B&B)의 가지치기(Pruning)**: B&B에서 상태 공간 트리를 탐색할 때 Bound 값을 어떻게 계산하느냐에 따라 탐색 속도가 극명하게 갈렸습니다. 초기에 Bound 설계를 느슨하게 했을 때는 불필요한 노드를 너무 많이 탐색하여 실행 시간이 기하급수적으로 늘어나는 문제를 해결하는 것이 까다로웠습니다.
- **포매팅 및 난수 제어**: 모든 알고리즘에 대해 완벽하게 동일한 조건(동일 난수)을 보장하기 위해 난수 생성기의 시드를 고정(`std::mt19937`)하는 과정과, 과제 명세에 제시된 테이블 UI 양식에 맞춰 정렬된 출력을 구현하는 작업에 생각보다 많은 시간이 소요되었습니다.

**2. (b) 원래 코드 아이디어와 참고한 코드(온라인 등) 사이의 주요 차이점**
- **동적 계획법 (DP)**:
  - *원래 아이디어*: 단순히 $N \times W$ 크기의 2차원 배열 공간을 할당하여 전체 표를 채워나가는 직관적인 방식이었습니다.
  - *참고한 코드의 차이점*: 메모리 제약을 해결하기 위해, 현재 아이템을 판단할 때는 직전 아이템의 데이터(이전 행)만 필요하다는 점을 활용해 **슬라이딩 윈도우 2D 배열(`dp[2][W]`)** 기법을 적용했습니다. 이를 통해 공간 복잡도를 $O(W)$ 수준으로 극적으로 줄일 수 있었습니다.
- **분기한정법 (B&B)**:
  - *원래 아이디어*: 재귀 호출을 이용한 깊이 우선 탐색(DFS) 기반의 백트래킹을 고려했습니다.
  - *참고한 코드의 차이점*: `std::priority_queue`를 이용해 가치가 가장 높을 것으로 예상되는 노드부터 먼저 탐색하는 **최고 우선 탐색(Best-First Search)** 방식을 차용했습니다. 또한, 상한(Bound) 값을 계산할 때 **Fractional Knapsack의 결과값**을 활용하도록 구현하여, 가지치기의 효율을 극대화한 것이 가장 큰 차이점이었습니다.

**3. (c) 이 과제를 통해 배운 점 (What you learned)**
- 동일한 0-1 배낭 문제라 할지라도 **알고리즘 설계 기법에 따라 성능 차이가 얼마나 큰지** 직접 눈으로 확인할 수 있었습니다. Brute Force는 $N=31$만 되어도 약 1.5초가 넘게 걸렸지만, DP나 B&B는 $N=10,000$처럼 데이터가 방대해져도 수 초 내외로 현실적인 시간 안에 문제를 해결했습니다.
- Branch and Bound를 구현하면서 **Fractional Knapsack** 방식이 B&B의 훌륭한 휴리스틱(상한선) 도구로 활용될 수 있다는 점을 깊이 이해하게 되었습니다. 단순한 그리디 접근이 다른 복잡한 알고리즘의 성능을 가속하는 재료가 된다는 사실이 흥미로웠습니다.
- 운영체제나 컴파일러에 의존하지 않고 객관적이고 공정한 성능 테스트를 진행하기 위해 **단일 난수 시드 고정**과 벤치마킹 설계가 중요하다는 것을 체감했습니다.
